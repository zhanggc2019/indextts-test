# IndexTTS 并发测试台

一个 Windows 本地测试页面，使用 `GET /api/v1/voices` 查询可用音色，使用 `POST /api/v1/tts/synthesize` 做语音合成。默认拿到 `audio_url` 就算成功，也可开启音频下载测试。不需要安装 npm 依赖；需要 Node.js 20 或更高版本。

## 准备环境与 Key

| 准备项 | 是否必需 | 获取或配置方式 |
| --- | --- | --- |
| Node.js 20 或更高版本（包含 npm） | 必需 | 从 [Node.js 官方网站](https://nodejs.org/) 安装，执行 `node --version` 检查 |
| 应用 API Key | 必需 | 向 TTS 服务管理员申请，须能访问音色列表和原生合成接口；通过 `TTS_API_KEY` 设置 |
| Git | 使用 git clone 时需要 | 也可在仓库页面选择 Code → Download ZIP 并解压 |
| MinIO Access Key / Secret Key | 客户端无需准备 | 由 TTS 服务端配置；本工具只使用服务返回的完整下载 URL |
| 管理员 Token / GitHub Token | 使用测试台无需准备 | 运行项目只需要应用 API Key |

本工具默认访问 `https://tts.lanyun.net`，也可在页面更换兼容的 TTS 服务地址；须能访问所选服务及其返回的音频存储域名。没有 npm 第三方依赖，无需执行 `npm install`。页面仅监听本机地址，不需要部署服务器。

## Windows 快速开始

在 PowerShell 执行：

```powershell
git clone https://github.com/zhanggc2019/indextts-test.git
cd .\indextts-test
node --version
$env:TTS_API_KEY = '替换为管理员提供的应用 API Key'
.\启动测试台.cmd
```

下载 ZIP 时，在解压后的工程目录打开 PowerShell，从设置 `TTS_API_KEY` 那一步开始。该变量只在当前窗口及其启动的服务中生效。保留启动服务的窗口，关闭它会结束测试。成功启动后，页面应显示“本地服务在线 · 凭据已加载”和可用音色数量。

如果希望以后直接双击启动，可在 PowerShell 中设置当前 Windows 用户的环境变量：

```powershell
[Environment]::SetEnvironmentVariable('TTS_API_KEY', '替换为你的应用 API Key', 'User')
```

双击 `启动测试台.cmd` 时，脚本优先使用当前进程的凭据环境变量；缺少时会依次补读 Windows 用户、系统环境变量，即使 Orca 或终端尚未刷新环境也可加载。启动脚本会跳过未加载凭据的旧服务，另选空闲端口启动，不会停止旧进程。修改 Key 后仍需关闭已加载旧 Key 的服务并重新启动，刷新网页不会更新凭据。直接使用 `node server.mjs` 时仍须保证启动终端已加载变量。不要将真实 Key 写进项目文件并上传；项目不会自动读取 `.env` 文件。

如需取消持久配置：

```powershell
[Environment]::SetEnvironmentVariable('TTS_API_KEY', $null, 'User')
```

## 启动与端口

双击 **启动测试台.cmd**，保留弹出的服务窗口，浏览器会打开 <http://127.0.0.1:8765>。

启动脚本会复用已经运行且支持定时启动、随机音色、一键清空历史及 MinIO 交付请求头的版本；如果默认端口被旧版或其他服务占用，则自动选择 8766～8775 中可用的端口，不会停止旧进程。并发数已取消 32 上限；HTTP 连接池也不再限制为 64 个活动连接。

页面不再固定使用一个音色。开始测试前用应用 Key 查询可用音色列表（8 秒总超时，失败或列表为空则拒绝开测），按种子打乱后逐条不放回使用，用尽后再打乱。各并发档位从相同音色序列起点开始，预热使用独立序列；如果当前只有一个可用音色，页面会说明。音色查询不计入合成耗时，也不在每条合成时重复查询。报告记录音色池、随机种子、各音色结果，页面及 JSON/CSV 逐请求记录实际 `voiceId` 和 `voiceName`。这些是混合音色的性能结果。旧固定音色历史仍可查看；API 保留显式 `voiceMode=fixed` 的兼容能力，页面新测试始终为随机音色。

历史菜单旁的 **“一键清空历史”** 会清空当前服务的历史列表，把全部本工具生成的快照、报告和抽样音频移入 `data/.history-trash/<归档编号>/`，页面提示完整归档位置。可在停止服务后从归档目录移回 `data/` 恢复。未加载到菜单中的更早记录也会归档；文本语料、API Key、无关文件保持原位。测试运行/准备中不允许清空，磁盘上其他服务仍在运行的测试也会阻止清空。这里只清空本地历史，不删除远端音频；归档不会自动永久删除。

所有新合成请求（包括预热）均发送 `X-Audio-Delivery: minio` 和 `X-Audio-Purpose: live_socket`，申请 MinIO 音频交付。报告及 JSON 配置记录请求的交付方式和用途；实际结果仍以每条响应的 `audio_storage`、`audio_url` 为准。服务端未启用 MinIO 或上传失败/超时可能回退为本地地址，保留真实返回值，不修改域名。下载音频时不转发这两个请求头或 API Key。历史报告不补填新的请求头。

也可以在本目录运行：

```powershell
node .\server.mjs
```

如果页面已经打开且服务仍在运行，直接使用当前页面即可，不要重复启动。关闭启动窗口或按 Ctrl+C 可结束服务。

## API Key

服务端优先读取环境变量 `TTS_API_KEY`。未设置时，仅当你显式设置了 `TTS_DOC_PATH`，才从对应的本地 Markdown 文档读取 `| API Key |` 行中反引号包围的值。仓库不含真实 Key，也不再依赖开发者电脑的固定文档路径。推荐按“Windows 快速开始”直接配置 `TTS_API_KEY`。

页面只接收“凭据是否已加载”，不会接收 Key；下载音频不携带 Key。如已有本机保存的凭据文档，可以用以下替代方式：

```powershell
$env:TTS_DOC_PATH = 'D:\你的目录\IndexTTS-API调用文档-含APIKey.md'
node .\server.mjs
```

支持的环境变量：

| 变量 | 说明 |
| --- | --- |
| `TTS_API_KEY` | 应用 API Key，优先于文档读取 |
| `TTS_DOC_PATH` | 可选；含 API Key 的本地 Markdown 文档路径，仅在未设置 `TTS_API_KEY` 时使用 |
| `TTS_BASE_URL` | 默认 `https://tts.lanyun.net` |
| `PORT` | 本地页面端口，默认 `8765` |
| `TTS_DATA_DIR` | 原始结果和音频目录，默认项目内 `data/` |
| `TTS_CORPUS_PATH` | 文本语料 JSON 路径，默认项目内 `text-corpus.json` |

## 使用

**测试音频下载默认关闭**：合成接口成功并返回有效的 HTTP/HTTPS 音频链接即算成功，预热和正式测试都不发起音频下载、不校验 WAV、不保存本地录音。并发槽位在获取链接后立即补位，下载耗时/TTFB 留空，全流程耗时截至获取链接；URL 可在请求明细中查看。链接缺失或合成失败仍记为失败，此模式不验证链接是否能下载。

需要验证完整交付时，在测试配置里将 **“测试音频下载”** 切换为 **“开启 · 合成并下载音频”**，恢复下文的合成→下载流程和本地试听。此选择同时适用于立即测试、定时测试和预热，Markdown、JSON、CSV 报告记录测试口径；旧历史记录按原有下载测试口径查看。更新后请重启本地服务，再刷新页面；启动脚本不会复用缺少此开关的旧服务。通过本地 API 开测时，可传布尔值 `downloadAudio: true` 开启下载，省略或传 `false` 则跳过下载。

1. 页面自动查询可用音色，每条请求按随机序列选取音色，无需填写固定 `voice_id`。默认从仓库附带的 `text-corpus.json` 中取词：语料来自 `task-media-20261030.csv` 的“合成文字”列，含 1104 条去空、去重后的完整文本，每条 7～80 字。不需要提前上传或准备原 CSV；也可切换为“手动输入文本”，每行一条。
2. 选择压测模式。**阶梯测试**默认顺序运行 **4 → 8 → 16 → 24 → 32 并发**，每轮持续 10 分钟；**单档测试**可单独填写 任意正整数的固定并发数和 0.01～168 小时的持续时间，例如 8 并发持续 2 小时。并发是同时在途的“合成 → 下载”链条数；一条结束立即补位。请求总数由响应速度决定，不设置固定次数。阶梯最多 8 档，每档 1～60 分钟。
3. 展开“更多参数”调整语言、语速、音量、预热次数。合成默认超时 20 秒，下载默认超时 10 秒；可以调小，服务端拒绝超过这两个上限的设置。
4. 点击一次“开始 50 分钟压测”。先串行预热（默认 0 次），随后自动运行所有轮次；预热失败则停止正式测试。10 分钟到时停止新增请求，等本轮在途请求完成或按既有超时结束后，自动进入下一轮。各轮在途请求不重叠。总用时为 50 分钟加各轮收尾时间。只有一个任务能同时运行。
5. 完成后查看档位对比和明细，点击“试听”播放已下载到本地的 WAV；URL 链接打开远端原始音频。
6. 全部结束后自动在 `data/` 保存一份覆盖所有轮次的 Markdown 汇总报告、CSV 全部请求明细和 JSON 原始快照，也可从页面一键导出。报告包含整场总览、每档成功率、超时/失败数、合成/下载分位数、吞吐量、实际发压/收尾时间和原句来源。运行中导出是当前快照。

页面用五个轮次块显示等待、持续发压、在途收尾、已完成状态，并显示当前轮倒计时。关闭浏览器页面不会终止任务，本地 Node 服务必须持续运行，测试期间避免电脑休眠。持续模式失败后该并发槽位最多间隔 1 秒再启动新请求，避免异常时瞬间连续发压；不重试失败原请求。

单档模式只显示一个并发档位，按设置的小时数持续运行，到时停止新增请求并收尾，随后保存同样的完整报告。阶梯模式和单档模式运行中都可点击 **“停止并生成报告”**：立即停止发压，取消本地在途连接，不再启动后续轮次；已成功/失败的记录保留，在途请求单独标记为取消，后续轮次标记为未执行。停止后自动在 `data/` 保存 Markdown 部分报告、CSV 和 JSON；页面“停止报告 .md”及 CSV/JSON 按钮可下载。报告记录停止原因、时间和“部分结果”范围，重复停止不会覆盖原来的停止时间。即使没有成功请求也会输出报告。

请求会调用真实线上服务。所有请求均不自动重试。点击“停止测试”取消本地在途连接及待启动任务；不能保证服务端推理随之结束。超时也不表示远端没有生成音频。

超时是从各阶段发起 HTTP 请求开始计算的总时限，覆盖连接、等待响应、读取完整响应体；音频下载中的所有重定向共用同一个 10 秒截止时间。合成超过 20 秒或下载超过 10 秒，立即断开本地连接、记为失败并释放并发槽位，继续下一条任务。单条合成与下载的网络等待合计最多 30 秒，不含本地排队及写盘。页面调用本地 API 最多等待 10 秒，连续 3 次读取状态失败后停止自动重连并提示刷新。历史测试报告中的原始超时配置保留，新测试表单会限制在当前上限内。

每场测试开始时生成新的随机种子，将 1104 条 CSV 文本洗牌后逐条使用；全部用完再以新的可复现种子洗牌循环，持续测试不受语料条数限制。各并发档位从相同文本序列起点取词；响应速度不同，实际请求数和使用的文本数量也可能不同。报告记录各档实际平均字数，便于判断文本长度影响。预热另抽取且不计统计。页面文本框展示语料样例，实际用词见请求明细；手动输入模式每行一条，持续轮换。

Markdown 报告记录语料文件名、列名、随机种子、语料及原始文件 SHA256、正式抽样文本和来源媒体 ID / 记录号。JSON、CSV 逐请求记录实际文本、字数、来源编号；记录号从 CSV 第一条数据开始计为 1，不含表头。JSON 配置还包含预热文本。需要重放时，同一语料可通过本地 API 的 `samplingSeed` 指定报告中的种子。原始 CSV 中的历史合成耗时等字段不参与新测试统计。

## 在页面更换 TTS 地址

在左侧 **“TTS 服务地址”** 输入基础地址（例如 `http://192.168.1.100:8000`），点击 **“保存地址”**。无需填写 `/api/v1/tts/synthesize`；保存后立即生效，无需重启，并自动刷新可用音色信息。修改后须先保存，才能启动测试。

新服务须兼容现有音色列表和合成接口、`X-API-Key` 鉴权、合成 HTTP 201 响应及 WAV 音频下载；继续使用本地配置的 API Key。保存地址不代表已验证新服务可用，音色查询失败时页面会显示原因。

地址保存在数据目录的 `settings.json`（默认 `data/settings.json`），服务重启后优先使用该地址，再回退到 `TTS_BASE_URL` 或默认值；清空历史不会移除此设置。地址仅接受 HTTP/HTTPS，不允许携带用户名、密码、查询参数或片段。测试运行、准备或等待预约时，页面和后端都禁止更换地址；已有报告保留各次测试原本的服务地址。

更新代码后，首次使用页面设置需重启旧服务；启动脚本只会复用支持页面地址设置的版本。

## 定时启动

配置好阶梯或单档测试后，在 **“启动方式”** 选择 **“定时开始 · 一次性预约”**，填写低峰时段的日期和时间，再点击 **“预约定时测试”**。默认仍为立即开始。时间按浏览器所在电脑的本机时区输入，提交时转换为带时区的绝对时间；页面显示预约时间和启动倒计时。

预约由本地 Node.js 服务使用内置计时器执行，不增加 npm 依赖、数据库或调度服务。预约时保存配置和快照，到点后查询最新可用音色，再执行预热和正式测试。等待预约的时间不计入各档持续时间、吞吐量或页面的测试总用时；报告分别记录预约创建、预约启动及实际开始时间。

等待期间可点击 **“取消预约”**，会保留取消记录和报告，不发起合成请求。预约占用唯一任务槽位，不能同时预约或启动另一场测试，也不能清空历史；取消或结束后可重新开测。刷新或关闭浏览器不影响预约，重新打开页面会加载预约状态。

须保持本地服务运行、Windows 电脑唤醒。服务退出或重启后，未执行的预约显示为“服务中断”，需要重新预约，不自动恢复。电脑休眠、时钟调整或服务繁忙导致触发时已晚于预约时间超过 1 分钟，会保存失败报告并跳过，避免在高峰期补跑；一分钟内的延迟允许启动。音色查询失败则结束本次预约并保留错误，不自动重试。本功能为一次性预约，不提供每日重复任务或自动唤醒电脑。

本地 `POST /api/runs` 也支持可选字段 `scheduledAt`，值为带时区的 ISO 日期时间字符串（例如 `2026-11-11T02:00:00+08:00`），须晚于当前时间；省略或传空字符串时立即开始。`GET /api/runs/:id` 的 `config.scheduledAt` 保存毫秒时间戳，`startedAt` 是实际开始时间（未开始为 `null`），等待和准备状态分别为 `scheduled`、`preparing`。取消预约沿用 `POST /api/runs/:id/stop`。

## 测量口径

| 指标 | 范围 |
| --- | --- |
| 合成耗时 | 本地服务发起 POST → 完整读取 JSON；包含连接、服务端排队、模型推理、传输 |
| 下载耗时 | 发起音频 URL GET → 完整读入响应体；包含重定向，不含写盘 |
| 下载 TTFB | URL GET 开始 → 最终音频响应的首个非空数据块 |
| 全流程耗时 | 开始合成 → 音频完整读取并校验；不含本地排队与写盘 |
| 成功 RPS | 档位内全流程成功数 ÷ 档位墙钟时长；包含调度与写盘时间 |
| 成功率 | 全流程成功数 ÷ 已启动请求数；取消和未启动分别在明细中记录 |
| P50 / P95 | 最近秩算法；空样本显示“—” |

**接口没有给出可独立验证的模型内部推理耗时，无法直接测出纯模型推理时间。** 页面中的“合成耗时”是客户端观测值。所有请求从本机 Node 服务发送，因此结果代表本机至 API / 音频存储的网络环境。

每个并发槽位覆盖整条“合成 → 下载 → 校验 → 抽样写盘”链。合成成功但下载失败时，仍计入合成时长分布；下载及全流程分布只统计全流程成功样本。失败尝试耗时、阶段、HTTP 状态和请求 ID 保留在 JSON / CSV。成功 RPS 的分母包含本轮发压和收尾的实际墙钟时长。

音频按 WAV 内容检查，HTTP 200 的 HTML 或损坏数据会记为失败。API 文档约定这个原生接口返回 WAV。所有请求均完整下载并计时，持续模式只保留每档请求序号 1～3 中成功下载的录音，其余音频下载校验后释放；所有文本和计时仍完整保存。录音保存到本地之前结束下载计时。

每档请求较少时 P95 可能等于最大值。持续压测可通过延长时间或重复整场对照观察稳定性；未预热时首档可能包含冷启动，同文本也可能受未知缓存影响。该工具不控制服务端缓存，也不把最高观测 RPS 当作容量上限。

## 文件与结果

按照 `api-call-guide-2026-10-30.md` 补充返回信息。Markdown 报告的 **“全部请求音频 URL”** 章节逐条列出成功、失败、取消及尚未结束请求的编号、并发档位、状态、完整原始返回地址、下载请求地址和最后观测到的最终地址；完整保留签名查询参数。收到 URL 后即记录，不受本地抽样保存录音数量限制。没有收到地址时注明合成失败、合成中取消、未启动或历史未记录等原因。手动停止报告同样保留已取得的全部链接。历史测试重新导出可使用已保存的 URL，缺失的新字段不会补推。

页面逐请求显示完整音频链接，更多信息可展开查看。JSON/CSV 同步保留 `audioUrlOriginal`（接口原文）、`audioUrl`（解析后的地址）、`downloadRequestUrl`（传给下载客户端的地址）、`downloadFinalUrl`（最后观测地址）；CSV 的 `audioUrlNote` 记录缺少链接的原因。

报告另含 **“字幕与存储交付”**、**“服务端诊断”** 章节：记录音频 ID、创建/过期时间、`audio_storage`、服务端音频长度/大小、字幕数组/条数、`subtitle_mode`、`subtitle_url`、`subtitle_storage`，以及 `X-Request-ID`、`X-TTS-Worker`、`X-TTS-Batch-ID`、`X-TTS-Batch-Size`、`Server-Timing`、`Retry-After`。字幕数组在 JSON/CSV 中保存；不额外下载字幕，也不更改成功判定。服务端音频长度不是推理耗时；合成计时可能包含字幕对齐及存储交付。缺失的诊断字段保持为空，不进行推断，不自动重试。原有合成 20 秒、下载 10 秒总超时仍生效。

报告有独立的 **“下载失败专项分析”** 章节，页面也有同名面板，只统计真正的下载失败，用户取消下载单独计数。先按最后观测阶段汇总失败数和超时数，再逐条记录原始下载 URL、重定向后的最终 URL、错误类型与错误码、HTTP 状态、Content-Type、已接收字节数和 Content-Length、响应头和首字节到达时间、重定向链、连接是否复用，以及各阶段时间线。JSON/CSV 保留相同诊断字段，CSV 的 `downloadDiagnostics` 是转义后的 JSON；页面最多显示最近 100 条下载失败，整场报告包含全部。

点击专项面板的“仅下载失败 CSV”可单独导出这些失败，不混入合成失败、成功请求或用户取消。测试结束或手动停止时，除完整报告外会自动保存 `data/<测试编号>.download-failures.csv`。

阶段区分：URL 校验 → 等待可用连接 → DNS 解析 → TCP 连接 → TLS 握手（HTTPS）→ 请求发送 → 等待 HTTP 响应头 → 等待音频首字节 → 响应体读取；额外区分 HTTP 状态异常、重定向异常和音频内容校验失败。读取过部分响应后超时会记录实际已接收字节数；非 200 下载状态收到响应头即失败，不必继续等待错误响应体。所有重定向共用初始 GET 的总截止时间。复用连接时不虚构 DNS/TCP/TLS 开销。

这些是客户端网络事件观测，不能仅凭“等待响应头”就认定是服务端排队，也不能仅凭“响应体读取”就认定是存储故障，需要结合 URL、字节进度和服务端日志分析。旧测试没有记录的阶段显示“历史未记录/无法定位”，无法事后补推。实现基于 [Node.js HTTP 事件](https://nodejs.org/api/http.html#class-httpclientrequest) 和 [Socket 连接事件](https://nodejs.org/api/net.html#class-netsocket)。

- `server.mjs`：零依赖本地后端、阶梯工作池和计时。
- `net-client.mjs`：下载总截止时间、连接/响应阶段诊断与重定向跟踪。
- `public/`：中文前端页面、统计及报告生成。
- `text-corpus.json`：从 CSV 导入的纯文本语料与来源编号，不包含原 CSV 的历史耗时等其他字段。
- `data/<测试编号>.json`：原始快照，开始、每 5 秒、每档结束和任务结束时保存。
- `data/<测试编号>.md`：任务结束后自动生成的整场汇总报告。
- `data/<测试编号>.csv`：任务结束后自动生成的所有轮次请求明细。
- `data/<测试编号>/<请求编号>.wav`：持续模式每档前 3 条请求中的成功录音。
- `tests/benchmark.test.mjs`：使用本地模拟上游的自动验证，不访问真实 TTS API。

页面刷新后会加载正在运行或最近一次持续测试；旧版按次数测试可从历史菜单查看，新测试表单保持持续模式。页面只显示最近 200 条请求，整场统计和导出包含全部数据。服务意外结束时最多丢失最近 5 秒内未保存进度；重启会把未完成请求标记为取消，并显示“服务中断”，不自动恢复发压。历史菜单加载本地最近 50 份快照。数据默认不会自动删除。

服务仅监听 `127.0.0.1`，拒绝跨站写入。它用于本机测试，未部署到公网。

## 常见问题

- **提示未配置凭据**：使用新版 `启动测试台.cmd`，脚本会在当前进程缺少变量时补读 Windows 用户、系统环境变量，并跳过无凭据旧服务。若当前窗口设置过旧值，先执行 `Remove-Item Env:TTS_API_KEY -ErrorAction SilentlyContinue` 再启动；或关闭旧服务、在同一终端设置 `$env:TTS_API_KEY` 后直接运行 `node .\server.mjs`。仓库不附带 Key，`.env` 文件也不会自动加载。
- **查询音色失败或返回 401**：检查应用 Key 是否有效、Base URL 是否正确，以及当前网络能否访问服务。Key 必须有公共音色及合成访问权限。
- **仍返回 tts.lanyun.net 音频地址**：已发送 MinIO 交付请求头，但服务端可能未启用 MinIO，或上传失败/超时后回退。以报告中的 `audio_storage` 和完整 `audio_url` 为准。
- **打开了旧版本或错误端口**：查看启动窗口输出的实际地址。关闭旧服务，再从新工程目录启动；直接执行 `node .\server.mjs` 可避免启动脚本复用同机已运行的服务。
- **每轮是否等上轮结束**：到时停止新增请求，等待本轮合成、下载和校验完成，或失败/超时后再开始下一轮。客户端超时不保证远端合成任务已停止。
- **并发超过 32**：阶梯和单档均支持更大的正整数，活动连接池无 64 连接限制；实际可达到的并发受本机资源、网络和服务端容量影响。

`data/`（含清空历史后的归档）、本地环境配置、日志和录音被 Git 忽略。报告包含完整音频 URL 和可能有有效期的签名参数，请按实际用途保存和分享。

验证五档持续补位、定时截止、在途收尾不交叠、停止后不启动后续档位、语料循环、紧凑轮询包含全量统计、自动汇总保存，以及既有下载计时、凭据隔离、超时、预热、取消和报告读取。自动验证使用本地模拟上游和压缩到 1 秒的轮次，不调用真实 TTS 服务；正式 50 分钟压测由页面“开始”按钮启动。
